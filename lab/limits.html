the ceiling

Where GitHub Pages stops.

Two kinds of limit: numbers you can hit by accident, and capabilities that simply do not exist no matter how you configure the repo.

01The numbers

These are GitHub's published soft limits. Nothing deletes your site the instant you cross one — you get an email first.

LimitValueWhat happens past it
Published site size1 GBBuilds stop succeeding. Large media belongs on a CDN or in Releases.
Single file size100 MBGit itself refuses the push. Git LFS files are not served by Pages.
Bandwidth100 GB / monthSoft cap. Sustained overuse gets your site throttled or disabled.
Builds10 per hourExtra pushes queue. Does not apply to Actions-based deploys.
Build timeout10 minutesThe build fails. Big Jekyll sites need to be split or pre-built.
Deploy latencyup to ~10 minPlus CDN caching. A push is not instantly visible; hard-refresh.

02Can it / can't it

The second column is the honest answer, not the marketing one.

You want to…Pages?What you actually need
Serve HTML, CSS, JS, images, fonts, PDFsYes—
Use React, Vue, Svelte, TailwindYesBuild locally or in Actions; commit the dist/ output.
HTTPS on a custom domainYesA CNAME file plus DNS records. Free certificate.
Run PHP / Node / Python / RubyNoRender, Railway, Fly.io, Vercel, a VPS.
A database (MySQL, Postgres, Mongo)NoSupabase, Firebase, PlanetScale, Turso.
Accept a contact formNoFormspree, Getform, Basin, or a serverless function.
User accounts and loginsNoAuth0, Clerk, Supabase Auth. The UI can live here; the auth cannot.
Hide an API keyNoAnything shipped is public. Proxy through a backend you control.
Server-side redirects, rewrites, custom headersNoNo .htaccess, no _redirects, no header control. Use a meta refresh or a real host.
Scheduled jobs / cronNoGitHub Actions on a schedule can regenerate files and commit them.
Password-protect the siteNoA public Pages site is public even from a private repo (Enterprise aside).
Server logs or analyticsNoClient-side analytics only: Plausible, GoatCounter, Umami.

03Rules that get sites taken down

From GitHub's Pages terms. Worth knowing before you build something on top of it.

Not a general file host

Pages is for a project or personal site. Using it as a CDN or backup drive is against the terms.

No commercial transactions

No storefronts, no payment processing, no SaaS running on Pages itself. Linking out to Stripe is fine.

One user site per account

Exactly one username.github.io. Everything else is a project site under a subpath.

No sensitive data

Published files are public. Treat the whole site as a press release.

Numbers can change — check docs.github.com/pages for the current values.
