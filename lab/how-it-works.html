the mechanics

git push, and a CDN starts serving your folder.

That is the entire model. Everything confusing about Pages comes from one of four places: the branch, Jekyll, the base path, or DNS.

01Turning it on

Repository → Settings → Pages → Source: Deploy from a branch → main / / (root) → Save.

git add -A
git commit -m "Add site"
git push origin main
# wait ~1 minute, then open the URL shown in Settings → Pages

The green checkmark next to your commit is the deploy. Click it to read the build log when something goes wrong.

Root path//my-app/ — the trap below
How manyone per accountunlimited

This repo is a user site, so / is the real root and absolute paths behave normally.

On a project site, <img src="/logo.png"> resolves to username.github.io/logo.png — outside your project — and 404s. That single slash is the most common Pages bug. This template uses relative paths (assets/css/style.css, no leading slash) everywhere, so it works unchanged in either layout.

03Jekyll, and why .nojekyll is in this repo

Pages runs every push through Jekyll by default. Jekyll ignores any file or folder starting with an underscore unless it understands it, so a React or Vite build with _next/ or _assets/ silently loses files.

Keep Jekyll

Write Markdown, get Liquid templates and a blog engine for free. Add _config.yml and _posts/.

Skip Jekyll (this site)

An empty .nojekyll file at the root. Every file is served exactly as committed. Required for most JS build output.

Check it yourself: ls -a in the repo root shows the .nojekyll file that makes this page load its assets/ folder reliably.

04Custom domain

# 1. At your DNS provider, for an apex domain (example.com):
A     @   185.199.108.153
A     @   185.199.109.153
A     @   185.199.110.153
A     @   185.199.111.153

# or for a subdomain (www.example.com):
CNAME www username.github.io.

# 2. Settings → Pages → Custom domain → enter it → Save
#    (this commits a CNAME file to the repo - leave it there)
# 3. Tick "Enforce HTTPS" once the certificate is issued (can take an hour)

Delete the CNAME file and the domain detaches on the next build. That is the usual cause of a site that "randomly went back to github.io".
