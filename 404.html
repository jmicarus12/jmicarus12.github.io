HTTP 404

No file lives at that path.

Which is the lesson: GitHub Pages answers a URL by looking for a matching file on disk. No file, no page. There is no router, no controller, no rewrite rule to intercept it.

You are seeing this custom page instead of GitHub's grey default because the repo contains a 404.html at its root. That is the whole mechanism.

⚠Note the paths in this file

Every other page in this template uses relative links. This one cannot: a 404 can be served at any depth (/a/b/c/nope), so its CSS and links must start with / to resolve. On a project site those leading slashes would need the project name in front — one more reason user sites are simpler to start with.

Tip: an SPA on Pages can copy index.html to 404.html so deep links boot the app.
